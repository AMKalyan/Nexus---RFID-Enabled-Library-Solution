# Interface Design

This document defines the contracts between Nexus and everything around it. The live OpenAPI specification is generated by FastAPI at `/api/docs` and exported to `docs/08-operations/openapi.json` at release. The tables below are the design-time contract the code is built against.

## 1. REST API (`/api/v1`)

All endpoints use JSON, except `/ncip` (XML) and the report exports. Errors always use the shape `{"error": "<message>", "code": "<ERR_CODE>"}`.

| POST | `/auth/smartcard/challenge` | public, rate-limited | `{reader_code}` → `{challenge_id, expires_in}` |
| POST | `/auth/smartcard` | public, rate-limited | `{reader_code, challenge_id}`. Completes a login started by a `CardTapped` event (see §2.4) |

## 2. RFID middleware contract

### 2.1 Device authentication
Each device has a code and an API key, sent in the header `X-Device-Key`. The key is stored hashed in `device.api_key_hash`.

### 2.2 Event envelope (device → Nexus)
`POST /api/v1/devices/{code}/events`
```json
{
  "event_id": "7b0d3c1e-2f0a-4c55-9a3c-0b5f2a1f9e10",
  "device_type": "gate",
  "type": "GatePassage",
  "occurred_at": "2026-10-05T10:15:02Z",
  "epcs": ["E2801160600002084A5B1C01"],
  "payload": { "direction": "out", "security_bit": true, "offline_decision": false }
}
```
Response: `202 {"status": "accepted"}`, or `200 {"status": "duplicate"}` if this `event_id` was already processed.

| Event type | Sent by | Payload |
|---|---|---|
| `Heartbeat` | all | `{firmware, uptime_s}` |
| `TagsRead` | staff_station, handheld | `{session_id?, mode: "single"\|"bulk", rssi?}` |
| `GatePassage` | gate | `{direction: "in"\|"out", security_bit, offline_decision}` |
| `CardTapped` | smartcard_reader | `{card_uid}` (masked in logs) |
| `Footfall` | gate | `{in_count, out_count, window_s}` |

### 2.3 Commands (Nexus → device)
Commands are queued per device and delivered over the device's WebSocket `/api/v1/devices/{code}/ws`. A device without a socket picks them up from `GET /devices/{code}/commands`.

| Command | Target | Parameters | Expected ack |
|---|---|---|---|
| `ReadTags` | staff_station, handheld | `{mode}` | `TagsRead` event |
| `WriteTag` | staff_station | `{epc, target_ref, security_bit}` | `{ok, epc}` |
| `SetSecurityBit` | staff_station | `{epc, value}` | `{ok}` |
| `Beep` | handheld, staff_station | `{pattern: "ok"\|"warn"\|"error"}` | — |
| `Light` | handheld, gate | `{color: "green"\|"amber"\|"red", ms}` | — |
| `CapturePhoto` | camera | `{gate_event_id}` | `{jpeg_base64}` |

Reliability:
- Commands time out after 3 s and are retried with exponential backoff (3 attempts), then marked failed.
- Events are idempotent by `event_id`.
- A device is `offline` when its last heartbeat is more than 30 s old.

### 2.4 Smart-card login handshake
1. The login page asks for a challenge (`POST /auth/smartcard/challenge {reader_code}` → `{challenge_id}`) and waits on `/ws/live`.
2. The reader sends a `CardTapped` event. The middleware resolves the UID through `CredentialProvider` and binds the result to the open challenge for that reader.
3. The UI calls `POST /auth/smartcard {reader_code, challenge_id}` and receives tokens. Challenges expire after 60 s and are single-use.

## 3. Interoperability

### 3.1 NCIP 2.0 adapter (subset; no conformance claimed)
`POST /ncip`, `Content-Type: application/xml`, authenticated with an agency key header.

| NCIP message | Maps to | Response elements |
|---|---|---|
| `LookupUser` | `MembersService.lookup` | UserId, UserName (masked), block/fine summary |
| `CheckOutItem` | `CirculationService.checkout(channel=ncip)` | ItemId, UserId, DateDue |
| `RenewItem` | `CirculationService.renew` | ItemId, DateDue |
| `CheckInItem` | `CirculationService.checkin` | ItemId, UserId |

Refusals become an NCIP `Problem` element whose `ProblemType` carries the Nexus refusal code. Messages not implemented return `Problem/ProblemType = Unsupported Service`.

### 3.2 SIP2 adapter boundary
Interface `Sip2Adapter.handle(message: str) -> str`. The mock implementation supports:

| Request | Response | Purpose |
|---|---|---|
| `23` Patron Status | `24` | Member status, block flags |
| `11` Checkout | `12` | Check-out |
| `29` Renew | `30` | Renew |
| `09` Checkin | `10` | Check-in |
| `99` SC Status | `98` | Health |

A TCP listener (port 6001) wraps the same handler and is disabled by default (`SIP2_LISTENER_ENABLED=false`). Checksums and sequence numbers are generated, and verified when present.

## 4. Integration adapters

| Interface | Methods | Mock behaviour | Config key |
|---|---|---|---|
| `NotificationChannel` (`email`, `sms`, `print`) | `send(message) -> DeliveryResult` | Writes `.eml` / `.txt` / `.pdf` into `outbox/` and marks sent; can be configured to fail N times to exercise retry | `ADAPTER_EMAIL`, `ADAPTER_SMS`, `ADAPTER_PRINT` |
| `CameraProvider` | `snapshot(camera_code, context) -> bytes` | Generates a JPEG with the gate, time and accession number drawn on it | `ADAPTER_CAMERA` |
| `CredentialProvider` | `resolve(card_uid) -> StaffIdentity \| None` | Looks up `staff_user.smartcard_uid` | `ADAPTER_CREDENTIALS` |
| `LegacyIlmsConnector` | `get_bib(bib_no)`, `get_item(acc_no)`, `get_borrower(id)`, `iter_*()` | Reads `legacy_ilms` through the read-only role | `ADAPTER_LEGACY` |

Notification flow: services write to `notification_outbox`; the worker polls every 5 s, sends through the adapter, and retries with backoff up to 5 attempts.

## As built (release 1.0.2)

This document is the design-time contract. Where the implementation differs, the implementation and the [API guide](../08-operations/api-guide.md) are authoritative:

| Design | As built |
|---|---|
| Role refusal code `ROLE_NOT_PERMITTED` | Permission failures return `ERR_FORBIDDEN` (403); `ROLE_NOT_PERMITTED` is not used |
| `PATCH /devices` | Devices are registered (`POST /devices`) and their keys rotated; there is no update endpoint |
| `/admin/roles` read and write | `GET /admin/roles` only; roles change through `PATCH /admin/users/{id}` |
| Card login waits on `/ws/live` | It waits on its own socket, `/ws/card` |
| Device commands ReadTags, WriteTag, SetSecurityBit, Beep, Light, CapturePhoto | Nexus issues `Beep` and `Light`; the camera snapshot is taken through the camera adapter |
| NCIP LookupUser returns a masked UserName | It returns `BlockOrTrap` and `UserFiscalAccountSummary`, without the name |
| Audit filter `actor` | The filter parameter is `actor_id` |
| `/health` status in the body only | 200 when healthy, 503 when a check fails (DEF-016) |
